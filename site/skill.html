    Skill for Claude

    The Blue Book of UX Directives, packaged as a skill for Claude.

    The skill gives Claude the full text of the book. Claude then cites the exact directive, ID and title, instead of paraphrasing UX advice from memory. A finding becomes a rule anyone on the team can look up and check, so designers, engineers, product managers and QA argue from the book, not from taste.

    What it can do, and why

    • Cite exactly. The book is bundled whole, so the title is quoted, not recalled.
    • Find the directives for a topic. An index maps all 62 subcategories with their "Ask yourself" questions.
    • Audit what it is shown. Screenshots, code, specs, flows. Each finding comes as Violates / Evidence / Fix / Severity.
    • Write requirements traced to directive IDs.
    • Explain any ID, including the five repealed ones and what replaced them.

    What it cannot do, and why

    • See what it is not shown. A skill is text and instructions. It judges what is in front of it; a state nobody opened stays unchecked.
    • Measure on its own. Pixels, contrast and timing are measured only when the agent has a browser and uses it. Otherwise they are inferred from code, and the finding should say so.
    • Know your history. A deliberate decision looks like a defect unless it is listed as a decision.
    • Know thresholds the book does not state. The book names no numbers such as 3:1 for icons. Pair it with WCAG.
    • Replace research. Severity is a judgment by consequence, not data about your users.

    Install

    Claude.ai (Pro, Max, Team, Enterprise):

    1. Download ux-directives.skill from the GitHub repository. It is a zip of the ux-directives/ folder.
    2. In Settings > Capabilities, turn on code execution and file creation.
    3. In the Skills section, click Upload skill and choose the file.
    4. Find the skill in the list and toggle it on.

    Claude uses the skill on its own when a task calls for it. You don't need to name it.

    Claude Code:

    git clone https://github.com/AlehHaiko/UX-directives-skill.git
cp -R UX-directives-skill/ux-directives ~/.claude/skills/

    ~/.claude/skills/ makes the skill available in all your projects. To share it with a team, put it in the repository's .claude/skills/ and commit it. Claude loads it when relevant, or you type /ux-directives.

    First prompts

    Audit:

    Audit our account settings screen against the UX Directives. [screenshot]

    Find by topic:

    We're redesigning onboarding — new users get a 9-step tour before they can do anything. What does the Blue Book say?

    Requirements:

    Write acceptance criteria for an LLM that drafts support replies the agent can send or edit.

    Explain an ID:

    What does directive 22/02 say, and how does it apply to an icon-only toolbar?

    Make audits sharper

    1. Audit with fresh eyes. The agent that built a screen has learned it and skips what is missing. Run the audit in a separate agent that gets the page, its source, the skill and the list of accepted decisions, and not the task history. Measured once, on one page: four fresh agents found a missing way out in 4 of 4 runs; the builder's audit had missed it. Forcing a sweep through all 62 questions did not change the result and took about a quarter longer.
    2. Show every state. List input × element × state × theme, so the audit sees what was never on screen.
    3. Label the evidence: measured, inferred from code, or assumed.
    4. List accepted decisions, so they are not raised again as defects.
    5. Pair with numeric standards such as WCAG for thresholds.
    6. Triage. A fresh audit also stretches directives to fit; keep the findings that decide the case.

    Worked example: a consent banner

    The Google Analytics consent banner on this site was built with Claude Code and audited with the skill every round.

    Caught by the skill:

    • 25/03—Make sure state is inspectable. Reopened after "Allow analytics", the banner still said "It stays off unless you allow it." Fix: a state line per choice — "You allowed it. Current state is on."
    • 54/07—Treat alternative input methods as primary. The banner sat last in the page: 12 Tab stops before "Allow analytics". Fix: it now follows "Skip to content"; one stop.

    Missed, then found:

    • 18/06—Allow decisions to be deferred. Reopened from the footer, the banner had no way out except a choice. The owner noticed it; the builder's audit did not. Four fresh audits of the same build each named it under this directive. Fix: "Close" and Escape.

    The lesson is in the method: the book had the rule all along.

    Limits

    Severity is the skill's judgment, not research. Conclusions about screen readers come from the markup unless tested with one. The book states no numeric thresholds. Chapter 9 is still forming. The measurement above is one page and four runs: a signal, not a statistic.
